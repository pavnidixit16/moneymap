# Progress: daily check-ins, streaks and achievements

A calm habit loop: one check-in a day, a streak, a weekly calendar and a few
achievements. It measures consistency in looking after money, not spending less.

## Check-ins (`daily_checkins`, migration 7)

| How a day counts | Event | Kind |
|---|---|---|
| "I didn't spend anything today" → explicit confirmation | `checkIn("no_spend")` | `no_spend` |
| "I've already reviewed today's activity" → explicit confirmation | `checkIn("reviewed_activity")` | `reviewed_activity` |
| Saving or confirming any entry (manual, Smart add, statement, Gmail; not sample data) | database trigger on `transactions` insert | `reviewed_activity` |

Opening a page never counts; only these events do.

- **One per day:** `unique (user_id, local_date)`. Repeat taps, retries and two tabs find the existing row. The server reports "already checked in" instead of adding one.
- **Today only:** a database trigger refuses inserts for any day but today, in India time like every other date in MoneyMap. Changes are allowed up to 7 days back. The server clock sets `confirmed_at`.
- **No money:** a check-in never creates, changes or deletes a transaction and stores no amount. The copy never claims money was saved.
- **Corrections:** "Actually, I spent something today" sets the no-spend day to `needs_review`, so it stops counting. Recording an expense dated that day turns it back into a counted `reviewed_activity` day (trigger). Transactions are untouched. Achievements earned that same day which only the withdrawn day made possible are removed; earlier ones stay.

## Streaks and calendar (`src/lib/progress.ts`, pure and unit-tested)
- **Current streak:** consecutive confirmed days ending today, or ending yesterday while today is still open.
- **Missed day:** resets the current streak. The longest streak is kept.
- **Weekly calendar:** Monday to Sunday.

## Achievements (`achievements`)

| Key | Earned when |
|---|---|
| `money_mindful` | first confirmed check-in |
| `consistency_builder` | 5 counted days in one calendar week (Mon–Sun) |
| `transaction_detective` | 10 entries confirmed through Smart add review (typed, voice, statement, Gmail) |
| `streak_3` / `streak_7` / `streak_30` | a run of 3 / 7 / 30 consecutive counted days |

- **Evaluation:** worked out from saved history after each check-in and when Progress loads. That load catches days credited by the trigger.
- **Duplicates:** `unique (user_id, key)` means an achievement is earned once.
- **Celebrated once:** `celebrated_at` is set as soon as the celebration shows.

## Celebration and sound
- **Chime:** `public/sounds/milestone.wav`, a 1.2 s soft three-note sound generated by `scripts/make-chime.mjs`, with no service and no licence. Streak milestones add a spoken line through the device's built-in voice, where available.
- **Autoplay:** sound plays only right after the user's own tap. Celebrations found on page load show **Play sound** instead.
- **Muting:** "Celebration sounds: on/off" is stored per device.
- **Failures:** if the sound can't load or play, the visual celebration still shows, with a short note.
- **Accessibility:** celebrations are text in an `aria-live` region, never sound or colour alone. Reduced-motion users get no animation.
